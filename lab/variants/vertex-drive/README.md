# Vertex Drive Technology Atlas

A research system for the **Vertex Drive**: a structured, machine-checked registry of the technologies that might make Wayfarer's
pulsed fusion drive more capable, what physics they rest on, what they would need, how they interact, and what they would mean for
the 3D model. It is a lab variant (see `../../README.md`): nothing here is canon, and nothing in the approved ship reads it.

| File | What it is |
| --- | --- |
| `NOTES.md` | lab header, function, constraints, unknowns, decisions |
| `REPORT.md` | the findings: summary, most promising directions, convergence, barriers, proposed architecture, roadmap, decisions |
| `registry/technologies.toml` | the registry: 8 workstreams (VTX-01..08) and their technologies, one record each, stable IDs |
| `registry/sources.toml` | every cited source with finding, limits, relation and PMDS verification state |
| `registry/links.toml` | positive and negative interactions between technologies |
| `registry/generations.toml` | Vertex 0 (FDP-1), Vertex 1 (advanced engineering), Vertex 2 (canon-bounded Fiji), each change tied to a technology |
| `registry/decisions.toml` | technical conclusions vs owner approvals (canon, experiments) |
| `atlas.py` | validator and generator: `validate`, `render` |
| `convergence.py` | runs the generations through the FDP-1 calculator; benchmarks, thresholds, sensitivity bands, VTX-04 studies |
| `ATLAS.md`, `READINESS.md`, `figures/dependency_map.svg` | generated from the registry; do not edit |
| `results/convergence.json`, `results/CONVERGENCE.md` | generated by `convergence.py` |
| `tests/test_vertex_atlas.py` | validator, sync, V0 reproduction and canon-guard checks |

## Use

```
python3 lab/variants/vertex-drive/atlas.py validate      # duplicate IDs, missing attributes, broken references, cycles, enums, claims
python3 lab/variants/vertex-drive/convergence.py         # about 5 min, 4 processes
python3 lab/variants/vertex-drive/atlas.py render        # regenerate ATLAS.md, READINESS.md and the dependency map
python3 lab/variants/vertex-drive/tests/test_vertex_atlas.py
```

## Adding or changing a record

1. Add a `[[technology]]` to `registry/technologies.toml` with the next free letter in its workstream (`VTX-03D`). Never renumber or reuse
   an ID; retire a record with `research_status = "RETIRED"`.
2. Cite sources by ID; add new ones to `registry/sources.toml` with their verification state. Do not cite what you have not read: mark
   it `UNVERIFIED` and say where the finding was taken from.
3. Every number goes in `[[technology.claims]]` with unit, basis (PUBLISHED, MODEL, ASSUMPTION, TARGET) and source.
4. A benefit the calculators cannot compute stays UNKNOWN. A generation change must name the technology that earns it and its basis.
5. Run `validate`, `convergence.py` if a generation changed, then `render` and the tests.

Credibility levels A/B/C here are **not** the PMDS material levels. Materials and purposes are cited by their PMDS IDs
(`data/materials/`), never copied.
